# 메모리 기반 협업 필터링 실험 결과

팀 베이스 코드의 사용자 기반 kNN을 사용해 Software, Video Games, 크로스 도메인 평가를 완료했다. Software 검증 RMSE로 k=20을 선택했다. 분야 내부 평점 예측은 전체 평균 기준보다 개선됐지만, 상위 10개 추천은 세 실험 모두 인기 상품 기준에 미치지 못했다.

## 구현과 담당 작업

- 기존 recsys.py의 UserKNN 및 평가 함수를 재사용했다. 추천 알고리즘을 새로 구현한 결과가 아니라, 제공된 구현을 분리 실행하고 검증·평가한 결과다.
- 사용자 평균으로 평점을 보정하고, 보정한 사용자 벡터의 코사인 유사도로 이웃을 선택한다.
- 양의 유사도만 반영하며, shrink=1.0으로 이웃의 영향이 약하면 사용자 평균 쪽으로 예측을 보정한다. 예측 평점은 1~5로 제한한다.
- 루트의 run_memory.py는 분야 내부 실험을, run_memory_cross.py는 크로스 도메인 실험을 실행한다. MF 및 하이브리드는 실행하지 않는다.
- chunk=32는 메모리 사용량을 줄이는 계산 묶음 크기다. 이웃 수 k나 추천 개수 10과는 다르다.

## k 선택

Software 검증 데이터로 비교했으며 테스트 결과로 k를 선택하지 않았다.

| k | 검증 RMSE |
|---|---:|
| 20 | 1.248996 |
| 50 | 1.249533 |
| 100 | 1.249761 |

가장 낮은 k=20을 선택했다. 차이는 작으며 통계적 유의성 검증은 수행하지 않았다. Video Games와 크로스 도메인에서도 k=20을 그대로 사용했다.

## 최종 비교표

RMSE는 낮을수록, F1@10은 높을수록 좋다. 인기 점수는 평점 예측이 아니므로 인기 기준의 RMSE는 보고하지 않는다.

| 실험 | kNN RMSE | 전체 평균 RMSE | kNN F1@10 | 인기 상품 F1@10 |
|---|---:|---:|---:|---:|
| Software | 1.282710 | 1.379446 | 0.005552 | 0.015714 |
| Video Games | 1.192280 | 1.252705 | 0.001870 | 0.006628 |
| 크로스 도메인 | 1.299327 | 1.118131 | 0.004238 | 0.022539 |

각 실험은 평가 대상과 데이터가 다르므로 서로의 점수를 단순 비교해 분야 간 우열을 판단하지 않는다.

## 평가 조건

- 난수 시드: 42. 추천 개수: 10. 실제 평점 4점 이상을 관련 상품으로 간주한다.
- 분야 내부: 사용자별 시간순으로 학습·검증·테스트 분할. 검증 약 10%, 테스트 약 20%이며 각 사용자에게 최소 1개씩 배정하므로 정확히 70/10/20은 아니다.
- 학습 데이터 전체를 유지하고 평가 사용자만 각 분야에서 10,000명 표본 추출했다. 검증 데이터는 최종 학습에 다시 넣지 않았다. 추천 후보에서는 학습·검증에서 이미 평가한 상품을 제외했다.
- Software 분할: 학습 859,781개, 검증 168,807개, 테스트 248,252개. 이 중 표본 사용자에 해당하는 테스트 평점을 평가한다.
- Video Games 분할: 학습 547,625개, 검증 108,748개, 테스트 158,213개. 이 중 표본 사용자에 해당하는 테스트 평점을 평가한다.
- 크로스 도메인: 공통 사용자 4,026명 중 805명의 게임 평점 9,723개를 전부 숨겼다. 나머지 공통 사용자 3,221명이 두 분야를 연결한다. 시간순 분할이 아닌 사용자 단위 보류 실험이다.
- RMSE는 평가 사용자의 보류 평점 전체에 대해 계산한다. Precision/Recall/F1은 관련 상품이 하나 이상 있는 사용자만 평균한다. 해당 사용자 수는 Software 8,044명, Video Games 8,355명, 크로스 도메인 801명이다.

## 제안서와 실제 구현 차이

제안서는 소프트웨어 평점만으로 사용자 유사도를 계산한다고 설명한다. 현재 팀 코드는 소프트웨어와 숨기지 않은 게임 평점을 합친 행렬로 사용자 평균·유사도 정규화를 계산한다. 이번 실험은 비교의 일관성을 위해 팀 코드를 유지했다. 평가 대상자의 게임 평점은 학습에 포함하지 않았다.

또한 제안서의 F1 평균 대상 설명과 달리 현재 코드는 관련 상품이 없는 사용자를 제외한다. 발표와 최종 보고서에 실제 조건을 명시하고 다른 담당자도 같은 평가 기준을 사용해야 한다.

## 해석과 한계

- Software와 Video Games에서는 kNN이 전체 평균보다 평점 오차를 줄였다.
- 세 실험 모두 상위 10개 추천 F1이 인기 상품 기준보다 낮았다.
- 크로스 도메인에서는 평점 예측도 전체 평균 기준보다 나빴다. 현재 방식의 분야 간 추천 효과가 입증됐다고 주장할 수 없다.
- 데이터 희소성, 유효 이웃 부족, 분야 간 취향 차이, 같은 예측 점수의 순위 처리 등이 가능한 원인이나 이번 실험으로 원인을 검증한 것은 아니다.
- k는 RMSE 기준으로만 선택했다. F1 최적화를 위해 선택한 k라고 설명하면 안 된다.

## 하이브리드 담당자에게 전달할 내용

최종 k=20, shrink=1.0, 시드=42와 동일한 데이터 분할·평가 함수를 사용한다. 원본 UserKNN의 fit(...) 및 scores(users) 인터페이스를 그대로 유지했다. 점수 결합 시 사용자와 상품의 인덱스 순서를 반드시 맞춰야 한다.

성능 지표 JSON만으로 하이브리드 예측을 만들 수는 없다. 담당자는 동일한 학습 자료와 Encoder로 UserKNN을 준비해 사용자별 상품 점수를 얻고 MF 점수와 결합해야 한다. 저장소에는 학습 모델이나 전체 예측 점수 행렬을 포함하지 않았다.

## 다시 실행하는 방법

저장소 루트의 data/에 평점 CSV를 준비한다. 데이터 파일은 Git에서 제외한다. 자세한 배치는 [데이터 안내](../data/README.md)를 참고한다. Python 3.12.14 환경에서 실행을 확인했다. 의존성 버전은 requirements.txt에 있다. 각자 컴퓨터에서 사용 가능한 Python 환경으로 다음을 실행한다.

```text
python -m pip install -r requirements.txt
python run_memory.py --eval-users 10000
python run_memory.py --category Video_Games --eval-users 10000
python run_memory_cross.py
```

Windows에서 python 대신 py를 사용하는 환경은 해당 명령을 바꿔 사용한다. 기존 컴퓨터의 전용 Python 경로나 PowerShell 설정에 의존하지 않는다.

결과의 k_source에는 실행했던 컴퓨터의 파일 경로가 기록되어 있지만, 실행 코드는 현재 폴더를 기준으로 결과를 찾으므로 다른 컴퓨터에서 사용할 때 해당 기록을 수정할 필요는 없다.

## 발표 설명 예시

사용자 평균으로 평점 성향을 보정한 사용자 기반 kNN을 평가했습니다. Software 검증 데이터에서 이웃 수 20, 50, 100을 비교해 RMSE가 가장 낮은 20을 선택했고, 같은 값을 게임 및 크로스 도메인 실험에도 적용했습니다. 분야 내부에서는 전체 평균보다 평점 예측 오차가 작았지만, 추천 목록의 F1은 인기 상품 추천보다 낮았습니다. 크로스 도메인에서는 두 비교 기준 모두를 넘지 못해, 현재 방식의 한계를 확인했습니다.
