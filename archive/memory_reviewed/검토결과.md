# 메모리 기반 협업 필터링 수정 및 재실행 결과

코드와 평가기를 보완한 뒤 제공된 Software·Video Games 평점 파일로 세 실험을 실제 재실행했습니다. 설정은 Software 검증 데이터에서 선택했고 테스트 전에 저장했습니다. 아래 수치는 저장된 결과에서 자동으로 작성했습니다.

## 핵심 결론

이웃 투표 추천은 분야 내부에서 인기 추천보다 높은 F1을 보였습니다. 반면 예상 평점을 정렬한 개선 kNN의 F1은 분야 내부에서 기존 kNN보다 낮았습니다. 따라서 기존의 “RMSE와 F1 모두 개선”을 하나의 동일 점수 모델의 성과로 설명하면 안 됩니다. 평점 예측과 투표 추천을 별도 변형으로 보고해야 합니다.

평균 보정만 사용하는 모델과의 RMSE 차이는 작았습니다. 이번 비교에서는 개선된 RMSE의 상당 부분이 사용자·상품 평균 보정에서도 얻어지며, 이웃 잔차의 추가 개선은 제한적입니다. 이는 특정 요인의 통계적 유의성을 검증한 결론은 아닙니다.

## 검증과 재현 정보

- 실제 실행 시간: 114.4초. 환경 및 데이터 SHA-256은 results/results.json에 기록했습니다.
- 선택된 설정: k=2000, 인기 보정 지수=0.0, 잔차 축소값=5.0.
- 검증 표본은 기존과 같은 2,000명이며, 설정은 전체 사용자 기준 투표 F1으로 선택했습니다. 평점 기반 변형을 별도로 최적화한 것은 아닙니다.
- 순위 동점은 인코딩 상품 인덱스 오름차순으로 통일했습니다. 기존 argpartition의 임의 동점 선택과 달라 특히 기존 kNN·전체 평균의 F1이 과거 수치와 달라질 수 있습니다.
- 원본 CSV에서 사용자·상품 중복 평점 없음, 평점 1~5 범위, 사용자별 최소 5개 평점을 확인했습니다.
- 크로스 도메인 대상의 게임 기록이 학습 데이터와 이웃 마스크에 포함되지 않음을 실행 중 확인했습니다.
- test_evaluation.py의 5개 테스트로 무관련 사용자 포함, RMSE 계산, 동점/후보 제외, 평균 보정 대조, Software 전용 유사도와 이웃 제외를 확인했습니다.
- 공통 사용자 평가 대상을 기존과 같은 시드로 선택했습니다. 데이터 분할과 사용자 표본을 바꾸어 성능을 높인 것이 아닙니다.
- 기존 테스트를 재사용했으며 새로운 독립 홀드아웃이나 다중 시드/통계적 유의성 검증은 수행하지 않았습니다.

## 팀에 전달할 내용

MF와 하이브리드는 evaluation.evaluate_model로 평가하고, 주 비교 표에는 개선 kNN 평점 순위의 RMSE와 F1을 함께 사용합니다. 이웃 투표는 별도 추천 방법으로 표시합니다. 하이브리드에 전달하는 scores()는 예상 평점이며, 투표 추천의 F1 성능이 자동으로 이전되지는 않습니다.

제안서 평가 정의에는 “F1@10은 전체 평가 사용자의 사용자별 F1을 평균하며, 관련 테스트 상품이 없는 사용자는 0으로 포함한다. 기존 결과와 비교하기 위해 관련 상품 보유 사용자 평균도 별도로 보고한다”를 반영하면 됩니다.

## 발표에 사용할 문장

사용자 기반 kNN을 평점 예측과 이웃 투표 추천의 두 변형으로 평가했습니다. 평점 예측은 사용자·상품 평균 보정을 적용해 오차를 낮췄으나, 보정값만 사용하는 대조 모델과 비교한 이웃 잔차의 추가 효과는 작았습니다. 이웃 투표는 분야 내부에서 인기 추천보다 높은 F1을 보였지만, 크로스 도메인에서는 인기 추천을 넘지 못했습니다. 모든 모델에 같은 평가 사용자와 추천 제외 규칙을 적용했으며, 두 변형의 성능은 구분해 보고했습니다.
